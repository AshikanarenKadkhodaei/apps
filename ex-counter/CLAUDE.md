# EXカウンター 引き継ぎメモ

モンスターストライクで「エクストラクエスト（EX）が出るまでに何周したか」を記録する、個人用のWebアプリ（PWA）。
iPhoneのSafariで開き、ホーム画面に追加してアプリのように使う想定。
App Storeには出さない（Apple Developer Programの年額費用を避けるため、Webで公開する方針）。

## 経緯
- 最初はClaude.ai上の公開ページで作ったが、ログインなしで開くと保存領域が一時扱いになり、タスクキルで記録が消えた。
- そのため、自分のドメイン（Netlify等）で普通のWebサイトとして公開し、localStorageで端末内に保存する形にした。

## ファイル構成
- `index.html` … 本体。HTML/CSS/JSすべてこの1ファイル。外部ライブラリ・Webフォントなし（オフラインで確実に動かすため）。
- `manifest.webmanifest` … PWA設定（名前、アイコン、standalone表示）。
- `sw.js` … Service Worker。ネット優先で取得し、失敗時にキャッシュを返す。
- `icon-192.png` / `icon-512.png` / `apple-touch-icon.png`（180px）… アイコン。

## 機能（v2・2026-09-21）
- クエストを複数作成・切り替え（上のボタン）。設定は右上の歯車から。
- 「＋1周」でハマり＋総周回を加算、「−1」で取り消し。
- 「EX出た！」→ パネルで勝ち／負け・ドロップ数（禁忌なら至宝・ラッキーリザルト）を選んで記録。**EXが出た周も1周に数える**（67周目で出たら n=67）。
- 確率アップ条件のスイッチ：オンの間の周回は `runs.b` に数え、遭遇率を条件あり／なしで分けて出す。
- ラック：使う前のラック＋勝ちのドロップ数。運極（既定99）まであと何体、今のペースで約何周かを表示。
- 運の良し悪し：設定した確率の目安 p から、今のハマり n 周で出ない確率 (1−p)^n と、9割の人が出る周回数を表示。
- **EXの一覧（確率アップ条件つき）**：クエスト追加パネルの「一覧から追加」で、名前・確率の目安・禁忌かどうか・条件が入る。名前を打って追加した場合も、一覧にある名前なら同じ情報が入る。画面のスイッチの下に条件を1行で表示し、押すと詳しい説明（出るクエスト・確かさ・目安・補足・出典・調べた日）が出る。
  - 確かさの印：公式（公式が発言）／検証（攻略サイトが周回して確認）／予想（噂・予想）／不明／自分のメモ（利用者が書き直した）。
  - 設定の「確率アップ条件のメモ」で書き直せる。書き直すと印が「自分のメモ」になり、元の情報は補足、元の出典は出典欄に残る。
  - **一覧は `index.html` の `PRESETS`**。新しいEXが出たら1行足し、`PRESET_DATE` を更新する。**数字と条件は攻略サイトの原文どおりに写す**（公式は具体的な条件と確率を公表していない。2026-09-21時点の出典はゲームエイト「EXステージの出現条件と攻略」2026-09-14更新ほか）。
  - 注意：アーキレットの「34ターン以内」「SS4体残し」は古い説。公式は「今の環境では試練10をクリアできる人は無条件で条件を満たしている」と発言（ゲームエイト、2026-06-19更新）。
- 統計：遭遇率・総周回・遭遇・平均・最短・最長・勝ち・負け。
- 自分で足す数え項目（例：2体ドロップ）。
- 投稿文：記録直後のお知らせか履歴の共有ボタンから。Xの投稿画面を開く／コピー。
- 取り消し：EX記録・履歴削除・設定保存・リセット・削除・読み込みの直後に「取り消す」が出る。
- バックアップ：JSONを書き出し／貼り付けて読み込み（旧v1形式も読める）。

## データ
- localStorageのキー `ex-counter-v2`。**旧 `ex-counter-v1` は消さずに残す**（v2が無いときだけ写して使う）。
- 形式：
  ```json
  {"v":2,"current":0,"quests":[{
    "name":"アムネディア","hamari":12,"runs":{"n":110,"b":11},"boost":false,
    "prob":{"n":1,"b":4},"goal":99,"luck0":20,"kinki":false,
    "extras":[{"name":"2体ドロップ","c":0}],
    "hist":[{"n":73,"t":1758400000000,"w":true,"d":1,"b":true,"s":false,"l":false}],
    "last":1758400000000,
    "info":{"from":"パラノヴィアの星墓","cond":"パーティの総ラック100以上","trust":"verified","note":"","src":"ゲームエイト…","date":"2026年9月21日"}}]}
  ```
  `hamari`＝前回のEXからの周回、`runs.n/b`＝条件なし／ありの総周回、`hist[].w`＝勝ち(true)負け(false)不明(null、v1から移した記録)、`d`＝ドロップ数、`b`＝条件あり、`s`＝至宝、`l`＝ラッキーリザルト、`info`＝確率アップ条件の情報（無ければ null）。
- **項目を足すときは `normQuest()` に既定値を1行足す**。読み込み・移行・バックアップの読み込みはすべてここを通るので、古いデータもそのまま読める。

## 公開手順
どちらか一方でよい。

**A. Netlify（手軽）**
1. このフォルダを https://app.netlify.com/drop にドラッグ、または `npx netlify-cli deploy --prod --dir .`
2. 無料アカウントに紐づけておくと、URLが消えない。

**B. GitHub Pages（更新を続けるならこちら）**
1. このフォルダをGitHubリポジトリにしてpush。
2. リポジトリの Settings > Pages で、mainブランチのルートを公開元に設定。

公開後、iPhoneのSafariでURLを開き、共有ボタン →「ホーム画面に追加」。

## 更新するときの注意
- `sw.js` の `CACHE` の名前（例：`ex-counter-v1` → `v2`）を必ず上げる。古いキャッシュが残らないようにするため。
- HTTPSでないとService Workerが動かない（Netlify/GitHub Pagesなら自動でHTTPS）。
- iPhoneでは、Safariで開いた場合とホーム画面から開いた場合で保存領域が別になる。利用者にはホーム画面から開くよう案内している。
- 公開URL（ドメイン）が変わると、保存データは引き継がれない。変える前にバックアップの書き出しを案内すること。
